# Platform Playbooks

Use platform-native packaging. Do not paste the same copy everywhere.

## YouTube Long Form

Best for:

- Deep tutorials.
- Build logs.
- Architecture walkthroughs.
- "I built X because Y kept breaking" stories.

Default structure:

1. Cold open: show the result or failure in the first 10-20 seconds.
2. Context: who this is for and what problem it solves.
3. Proof: repo, command, demo, test, or before/after.
4. Build/walkthrough: 3-5 chapters.
5. Takeaways: what to copy, what to avoid.
6. CTA: repo, plugin install, Substack/Medium writeup, GitHub issue.

Official reference:

- YouTube Shorts and video guidance changes: `https://support.google.com/youtube/answer/15424877`
- YouTube monetization policies: `https://support.google.com/youtube/answer/1311392`

## YouTube Shorts, TikTok, Instagram Reels

Best for proof compression:

- Show a tool working.
- Show a mistake and the fix.
- Show before/after.
- Show a one-command install.
- Show an agent failure loop in seconds.

Short script shape:

1. Hook: "My coding agent kept repeating the same mistake."
2. Visual proof: screen capture, terminal, diff, or broken output.
3. Turn: "So I built a skill/hook/MCP tool that..."
4. Payoff: show the fixed workflow.
5. CTA: "Repo is linked. I am writing up the teardown."

Platform notes:

- YouTube Shorts supports vertical/square Shorts up to 3 minutes, but keep most technical shorts shorter unless the proof needs time.
- TikTok's official creative guidance emphasizes native vertical video, hooks in the first seconds, people/voice, trend awareness, and testing variants.
- Instagram creator guidance emphasizes reach, engagement, account recommendations, and personalized account feedback.

Official references:

- YouTube Shorts length/status: `https://support.google.com/youtube/answer/15424877`
- TikTok creative best practices: `https://ads.tiktok.com/help/article/creative-best-practices`
- Instagram creator best practices hub: `https://about.fb.com/news/2024/10/best-practices-education-hub-creators-instagram/`

## X / Twitter

Best for:

- Sharp technical observations.
- Build-in-public threads.
- Release notes.
- Screenshots, terminal snippets, diagrams.
- Linking to GitHub, YouTube, Substack, or Medium.

Post patterns:

- Single insight: "The most expensive part of AI coding is not tokens. It is repeated mistakes that never become guardrails."
- Thread: problem -> failed attempts -> implementation -> result -> link.
- Launch: one-line value prop -> demo GIF/video -> install command -> repo link.
- Debate: concrete claim, evidence, question.

Current-rule reference:

- Creator monetization and eligibility can change; verify with X Help before advising monetization: `https://help.x.com/en/using-x/creator-revenue-sharing`

## Reddit

Best for:

- Real discussion.
- Asking for feedback.
- Sharing hard-won lessons in communities that permit it.

Rules:

- Read subreddit rules first.
- Participate before posting links.
- Prefer text posts that teach something even if the link is ignored.
- Ask a concrete question.
- Do not automate Reddit posting or replies without explicit review.
- Avoid repetitive self-promotion across communities.

Post pattern:

1. Describe the problem in community language.
2. Explain what you tried.
3. Share the result and tradeoffs.
4. Ask for critique.
5. Add a link only when allowed and genuinely useful.

Official references:

- Reddit spam policy: `https://support.reddithelp.com/hc/en-us/articles/360043504051-Spam`
- Reddit content policy: `https://redditinc.com/policies/content-policy`

## Medium

Best for:

- Polished essays and tutorials that can be discovered outside the immediate subscriber base.
- Durable, searchable writeups.
- Refined versions of build logs and agent failure analysis.

Structure:

- Clear headline.
- Short concrete intro.
- Sections with code/proof.
- Screenshots or diagrams where useful.
- Practical takeaway list.
- Link back to GitHub and joeblack.nyc.

Official reference:

- Medium Partner Program overview and quality expectations: `https://help.medium.com/hc/en-us/articles/25267383906711-Medium-Partner-Program-overview`

## Substack

Best for:

- Owning the audience relationship.
- Serial essays.
- Changelogs and field notes.
- More personal context than Medium.

Growth loop:

- Publish a clear recurring series.
- Use recommendations and cross-creator relationships.
- Promote GitHub/YouTube artifacts back to the newsletter.
- Keep archives useful and searchable.

Official reference:

- Substack recommendation/features guidance: `https://support.substack.com/hc/en-us/articles/360037455112-How-do-I-get-featured-on-Substack`

## GitHub

Best for:

- Proof.
- Installable artifacts.
- Technical credibility.
- Distribution through stars, forks, issues, releases, and READMEs.

Every promoted project should have:

- Clear README.
- Install command near the top.
- Demo GIF/screenshot if visual.
- Problem statement.
- Example workflow.
- License.
- Social preview image when appropriate.
- Pinned repo/profile alignment.

Official references:

- GitHub profile docs: `https://docs.github.com/en/account-and-profile/concepts/about-your-profile`
- GitHub profile README docs: `https://docs.github.com/en/account-and-profile/how-tos/setting-up-and-managing-your-github-profile/customizing-your-profile/managing-your-profile-readme`
